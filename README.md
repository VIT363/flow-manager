сервис FlowManager, точка входа для клиента (например, фронтенда). Он принимает файлы по REST, складывает их в MinIO, ведёт статус в БД и 
дирижирует асинхронной обработкой через Kafka, не блокируя клиента на долгой конвертации.

📋 Задача
Создайте сервис, доступный по REST, который принимает входящие запросы и перенаправляет их обработку в другие микросервисы — в нашем случае в 
сервис конвертации файлов.

Общая схема
FlowManager синхронно принимает файл от клиента, а тяжёлую конвертацию отдаёт через Kafka сервису конвертации и узнаёт результат отдельным событием. 
Статус файла по ходу обработки меняется так: «В обработке» → «Успешно» или «Ошибка».

Схема
Клиент (фронтенд)
│ 1. POST файл
▼
┌─────────────────┐   2. сохранить файл        ┌────────┐
│   FlowManager   │ ──────────────────────────►│ MinIO  │
│                 │   3. запись в БД:           └────────┘
│                 │      статус "В обработке"
└─────────────────┘
│ 4. событие с путём к файлу  ──►  Kafka topic "to-convert"
▼
┌────────────────────┐  читает исходник / пишет PDF   ┌────────┐
│ Сервис конвертации │ ◄─────────────────────────────►│ MinIO  │
└────────────────────┘
│ 5. событие с путём к PDF (успех/ошибка)  ──►  Kafka topic "converted"
▼
┌─────────────────┐
│   FlowManager   │  6. статус -> "Успешно" / "Ошибка",
│   (консюмер)    │     сохранить путь к сконвертированному файлу
└─────────────────┘

Статус файла:  "В обработке" ──успех──► "Успешно"
└─ошибка──► "Ошибка"

Загрузка файла

Реализуйте один REST-метод, принимающий на вход файл. Он должен:
 - сохранить файл в MinIO;
 - добавить в БД запись о том, что файл (с указанным путём в MinIO) находится в статусе «В обработке»;
 - отправить путь к файлу в событии через Apache Kafka.

Обработка результата конвертации

Сервис конвертации обработает файл и отправит в топик Kafka событие с путём до сконвертированного файла в MinIO. Получив это событие, FlowManager:
 - меняет статус на «Успешно» или «Ошибка»;
 - сохраняет в БД путь к новому (сконвертированному) файлу.

Дополнительные REST-методы:
 - метод, который по ID файла возвращает статус конвертации;
 - метод, который возвращает сам сконвертированный файл — при условии, что он уже готов.

Самая долгая операция — конвертация файла — выполняется асинхронно через Kafka. Клиент не ждёт её завершения: он получает ответ сразу, а 
статус узнаёт отдельным запросом. Это делает систему устойчивой к высокой нагрузке, частым запросам и большим файлам.
